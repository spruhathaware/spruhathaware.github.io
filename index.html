Case study · UX research

UTS Mobile App: redesigning ticket booking

Indian Railways passengers use UTS to book unreserved tickets, often on the platform and in a hurry. I mapped the booking journey, found where it broke down, and redesigned it from 8 steps to 5.

RoleUX research & UI design
ScopeBooking journey
ToolsFigma
Outcome8 → 5 steps (−37%)
The problem

Booking was slow and confusing for daily commuters

Too many steps8 steps to buy one ticket, which is a lot for someone booking every day.
Features were hard to findWeak information hierarchy buried key features.
No clear primary actionThe most important actions didn't stand out, so people hesitated.
Unnecessary screensRedundant screens and loading slowed every booking.
The redesign

A five-step booking flow

  1. STEP 1Select journey type
  2. STEP 2Choose origin & destination
  3. STEP 3Pick ticket type & passengers
  4. STEP 4Review journey details
  5. STEP 5Confirm & get ticket

Case study · Design operations

Design–Developer Collaboration

Good designs lose accuracy in the build when handoffs are unclear, specs go missing, and design and engineering stop talking. I set up a structured workflow for build validation, UI QA and issue tracking so the design intent survives to release.

RoleUX project manager
FocusDesign fidelity
ToolsCassini, Figma
TeamsDesign + Engineering
The challenge

What was going wrong

Builds didn't match designsUI inconsistencies between design files and product builds.
Specs were misreadDesign specifications were misinterpreted during implementation.
Bugs were caught lateDesign-related bugs surfaced only at the end of the cycle.
Too much back-and-forthDesigners and developers kept going round in circles on the same issues.
My approach

A four-part framework

Build & UAT validationTested every UAT build against the specs for layout, typography, spacing and interactions.
Bug tracking in CassiniLogged layout inconsistencies, missing components and interaction errors, and tracked each one until it was fixed.
Bridging design & engineeringClarified design intent with both teams so gaps were closed quickly.
Continuous design QAMoved design validation into the development cycle instead of leaving it for final QA.
Workflow

The delivery pipeline

Design delivery Developer build UAT build testing Cassini bug report Design–dev alignment Release
Impact

Results

Higher build accuracyBuilds matched the designs more closely
Issues caught earlierUI bugs found during development
Fewer gapsLess design–dev miscommunication
Smoother releasesMore efficient QA and releases

Tip for Spruha: if the 25% turnaround gain and 30% consistency gain from your Canvs role came from this workflow, add them here. Numbers make this case much stronger.

Takeaway

By giving both teams one consistent way to review builds and log UI issues, I helped set up a lasting collaboration framework, so the team could ship polished, consistent experiences without relying on heroics.
